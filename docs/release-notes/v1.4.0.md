## Joins CMED Estendidos

Extensão dos JOINs CMED para AMP e Fornecedores, permitindo consultar preços regulados pela ANVISA diretamente a partir de um produto comercial (AMP) ou de um fabricante (Supplier), além do JOIN já existente com AMPP.

### Funcionalidades

- **JOIN AMP+CMED** — `GET /api/v1/amp/:id/cmed` retorna AMP + VMP pai + preço CMED via `AMP.nu_nreg = CMED.nu_sanreg`
- **JOIN Supplier+CMED** — `GET /api/v1/suppliers/:id/cmed` retorna Fornecedor + lista de produtos CMED via `Supplier.nu_cnpj = CMED.nu_cnpj` com normalização
- **Normalização de CNPJ** — `CMEDRepository.GetByCNPJ` remove não-dígitos do CNPJ antes do JOIN, garantindo compatibilidade entre formatos (`12.345.678/0001-90` ↔ `12345678000190`)
- **Cache Redis** — Ambos endpoints utilizam cache Redis com TTL configurável. Graceful degradation: API funciona sem Redis (sem cache, query direta no PostgreSQL)
- **Parâmetro `dt_referencia`** — Ambos endpoints suportam `?dt_referencia=YYYY-MM-DD` opcional para consultar preços de uma data de referência específica
- **AMPCMEDUsecase + SupplierCMEDUsecase** — Usecases dedicados com cache Redis e graceful degradation

### Novos Endpoints

| Método | Rota | Descrição |
|--------|------|-----------|
| GET | `/api/v1/amp/:id/cmed` | Dados AMP + VMP pai + preço CMED (JOIN via Registro Sanitário) |
| GET | `/api/v1/suppliers/:id/cmed` | Dados Fornecedor + lista de produtos CMED (JOIN via CNPJ normalizado) |

### Uso

```bash
# AMP + VMP + CMED
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8094/api/v1/amp/1/cmed"

# AMP + VMP + CMED com data de referência específica
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8094/api/v1/amp/1/cmed?dt_referencia=2025-05-08"

# Fornecedor + lista de produtos CMED
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8094/api/v1/suppliers/1/cmed"

# Fornecedor + lista de produtos CMED com data de referência específica
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8094/api/v1/suppliers/1/cmed?dt_referencia=2025-05-08"
```

### Decisões de Arquitetura

- **D14**: `AMP.nu_nreg` (Registro Sanitário) como chave de JOIN AMP↔CMED — retorna registro CMED único por data de referência
- **D15**: Normalização de CNPJ em Go — remove não-dígitos (`regexp.MustCompile(`\D`).ReplaceAllString`) antes do JOIN, garantindo compatibilidade entre formatos com e sem pontuação
- **D16**: Supplier+CMED retorna lista de produtos — um fornecedor pode ter múltiplos medicamentos na CMED, diferente de AMP que retorna registro único

### Compatibilidade

- Sem breaking changes na API REST
- Todos os endpoints existentes permanecem inalterados
- CNPJ normalização é transparente — funciona com CNPJ formatado (`12.345.678/0001-90`) ou não formatado (`12345678000190`)
- Redis é opcional — API funciona normalmente sem ele (sem cache)
- Novos endpoints são aditivos e retrocompatíveis
